# VOTAGEX Roadmap

แผนพาตัวทดลอง UI (`/proto`) ไปเป็นเว็บแอปที่เพื่อนใช้ได้จริง ไฟล์นี้คือที่อ้างอิงกลางของทุกคนที่ทำโปรเจกต์
(คุณ, Claude, Gemini) ว่าตอนนี้มีอะไรแล้ว เวอร์ชันแรกจะมีอะไร และทำอะไรก่อนหลัง ตัดสินใจเรื่องไหนแล้วให้อัปเดตไว้ที่นี่

อัปเดตล่าสุด: 23 ต.ค. 2569 (ล็อกขอบเขตเวอร์ชันแรกแล้ว)

---

## 0. กติกา

- **ฟรีเท่านั้น** ไม่ใช้บริการที่ต้องผูกบัตร ถ้าโควตาฟรีไม่พอ ฟีเจอร์นั้นรอไปก่อน ไม่อัปเกรดเป็นแผนเสียเงิน
- **ทีละขั้น** ทุกขั้นมีเงื่อนไข "ถือว่าเสร็จเมื่อ" ขั้นถัดไปเริ่มเมื่อคุณยืนยันแล้วเท่านั้น
- **หน้าตา กับ ข้อมูล**
  - หน้าตา (สี ขนาด ระยะ เลย์เอาต์ แอนิเมชัน) แก้ได้ตลอด แม้ขึ้นระบบแล้ว
  - ข้อมูลหรือฟีเจอร์ (ช่องกรอกใหม่ หน้าใหม่ ใครเห็นอะไร) แก้ได้ง่ายจนถึงขั้น 2 หลังจากนั้นมีต้นทุนเพิ่ม
  - ฟีเจอร์ของเวอร์ชันแรกจึงล็อกตอนจบขั้น 1 ไอเดียฟีเจอร์ใหม่ไปลง backlog รอรอบถัดไป
- **Backlog** จดไอเดียใน GitHub Issues ไม่ใช่ในแชต ติดป้าย `must` / `should` / `could` / `later`
- **Commit** หนึ่งฟีเจอร์ต่อหนึ่ง commit ใช้ได้แล้วค่อย push ทุก push คือจุดที่ย้อนกลับมาได้

## 1. ตอนนี้อยู่ตรงไหน

ใน `votagex-react/` มี 2 แอป:

| | แอปเดิม (`/`, `/home`, `/trip/:id`) | ตัวทดลอง (`/proto`) |
|---|---|---|
| UI | เวอร์ชันแรก (MUI + CSS ของตัวเอง) | UI ใหม่สไตล์ ThaiWell ที่คุณปรับอยู่ |
| ข้อมูล | Firebase: ล็อกอิน Google, คอลเลกชัน `trips` | ข้อมูลตัวอย่าง เก็บในเบราว์เซอร์นี้เท่านั้น (localStorage) |
| หลายคนใช้ร่วมกัน | ได้ (เข้าร่วมทริปด้วยลิงก์) | ยังไม่ได้ กลุ่มและทริปร่วมเป็นแบบจำลอง |

**ข้อเสนอ:** ใช้ตัวทดลองแทนแอปเดิม ส่วนที่ดีของแอปเดิม (ตั้งค่า Firebase, ล็อกอิน Google, เข้าร่วมด้วยลิงก์) ย้ายมาใช้ในตัวใหม่ ที่เหลือเลิกใช้

### ตัวทดลองทำอะไรได้แล้ว

| ส่วน | ฟีเจอร์ |
|---|---|
| หน้าแรก | ปฏิทินเดือนที่พับเป็นสัปดาห์ (ปัดเปลี่ยนเดือน/สัปดาห์, 2 ธีม), ปฏิทินของฉัน/ของกลุ่ม, การ์ดสภาพอากาศสด (ท้องฟ้าเคลื่อนไหว ความแรงฝน PM2.5 วันหยุด นาฬิกา), แผนของวันพร้อมเช็คอิน, กล่องข้อความเหนือโปรไฟล์, งานที่เก็บไว้, ไปไหนดี?, ความทรงจำเมื่อปีที่แล้ว, ใช้จ่ายเดือนนี้ |
| กลุ่ม | กลุ่มเที่ยวพร้อมสีประจำกลุ่ม, ดูปฏิทินและทริปของกลุ่ม, จุดสีกลุ่มบนปฏิทินของฉัน, สร้าง/ดู/ลบกลุ่ม |
| แผน | รายการแผน, สร้างแผน (ค้นสถานที่ วันที่ กลุ่ม ใครไป), หน้าทริป 4 แท็บ (แผน/แผนที่/เงิน/ความทรงจำ), จุดแวะรายวัน, เช็กลิสต์ไปต่างประเทศ, หน้าสรุปหลังจบทริป |
| เช็คอิน | ปุ่มกดเอง, อัตโนมัติตามตำแหน่งขณะเปิดแอป (รัศมีตามประเภท อยู่นานพอ กดยกเลิกได้) |
| สถานที่ | เซฟจากลิงก์ TikTok/IG/Google Maps หรือค้นหา, อยากไป/เคยไป, หน้าแผนที่ |
| งาน | เก็บคอนเสิร์ต ตลาดนัด ป๊อปอัปจากลิงก์โพสต์ (อ่านชื่อ วันที่ เวลา สถานที่จากแคปชัน), แชร์ให้กลุ่ม, ใส่ลงแผนของวัน |
| เงิน | จดรายจ่ายหลายสกุล (อัตราแลกเปลี่ยนจริง), หารกับสมาชิก, ใครต้องโอนใคร, QR พร้อมเพย์ (เลขตัวอย่างเท่านั้น) |
| เก็บเงิน | กระปุกต่อทริปแยกหมวด, หยอด/ใช้, กระปุก 3D |
| โปรไฟล์ | สถิติ, จังหวัดที่สะสม, กลุ่ม, กระปุก, ตั้งค่า (ธีมปฏิทิน เช็คอินอัตโนมัติ), เครดิตแหล่งข้อมูล, โหมดสาธิต |

### บริการฟรีที่ใช้อยู่

| บริการ | ใช้ทำอะไร | ต้องมี key? | ข้อจำกัดที่ต้องระวัง |
|---|---|---|---|
| Open-Meteo (พยากรณ์ + คุณภาพอากาศ) | สภาพอากาศ, PM2.5 | ไม่ | ฟรีเฉพาะใช้แบบไม่หารายได้ |
| Photon (OpenStreetMap) | ค้นหาสถานที่ | ไม่ | ใช้อย่างพอดี: หน่วงการค้น + จำผลไว้ (ทำแล้ว) |
| MapLibre + OpenFreeMap | แผนที่ | ไม่ | — |

| ปฏิทินวันหยุดสาธารณะของ Google | วันหยุดไทย | ไม่ | เก็บเป็นไฟล์ รัน `npm run holidays` ปีละครั้ง |

## 2. เวอร์ชันแรก (MVP): ข้อเสนอ

**เวอร์ชันแรกมีไว้ทำอะไร:** เพื่อนกลุ่มหนึ่งวางแผนทริปด้วยกันและหารเงินกันได้บนมือถือ อะไรที่ช่วยเรื่องนี้คือ `ต้องมี` ที่เหลือรอได้

นี่คือข้อเสนอ ติ๊กข้อที่เห็นด้วย ย้ายข้อที่ไม่เห็นด้วย แล้วส่วนนี้จะถูกล็อก

### ต้องมี (เวอร์ชันแรก)

| ฟีเจอร์ | ต้องมี backend? | หมายเหตุ |
|---|---|---|
| ล็อกอิน Google + LINE | ใช่ | Google ใช้ของ Firebase ในแอปเดิม; LINE ผ่านตัวกลางบน Cloudflare Workers (ฟรี) ที่รับการล็อกอินจาก LINE แล้วออกบัตรผ่าน (custom token) เข้า Firebase |
| กลุ่ม + ลิงก์ชวน | ใช่ | เข้ากลุ่มจากลิงก์ ทุกคนในกลุ่มวางแผนได้ |
| แผนและจุดแวะ (สร้าง แก้ รายวัน แท็บแผนที่) | ใช่ | แชร์กันในกลุ่ม |
| ปฏิทินหน้าแรก: ของฉัน/ของกลุ่ม, การ์ดของวัน | ไม่ (อ่านจากแผน) | |
| เช็คอิน: กดเอง + อัตโนมัติ | ใช่ (เฉพาะผลเช็คอิน) | ตำแหน่งอยู่ในมือถือเท่านั้น |
| รายจ่าย หาร ใครต้องโอนใคร | ใช่ | |
| โอนคืนด้วย QR พร้อมเพย์ | ใช่ | แต่ละคนใส่พร้อมเพย์ของตัวเอง โหมดสาธิตยังใช้เลขตัวอย่าง |
| การ์ดสภาพอากาศ | ไม่ | ใช้ข้อมูลสดอยู่แล้ว |
| เซฟสถานที่ (ลิงก์/ค้นหา) | ใช่ | |
| ติดตั้งบนมือถือได้ (PWA) | ไม่ | มีไอคอนบนหน้าจอ เปิดเต็มจอ |

### ควรมี (ทำต่อจากนั้นไม่นาน)

| ฟีเจอร์ | หมายเหตุ |
|---|---|
| งานจากลิงก์ + แชร์ให้กลุ่ม | ตัวทดลองทำแล้ว รอที่เก็บข้อมูล |
| ความทรงจำ (ข้อความ + อารมณ์) | ยังไม่มีรูป |
| กระปุกเก็บเงิน | |
| หน้าสรุปทริป | |
| อัตราแลกเปลี่ยน วันหยุด PM2.5 | ทำแล้ว แค่เก็บไว้ |
| แจ้งเตือนจากแอป (Web Push) | ฟรีไม่จำกัดผ่าน Firebase Cloud Messaging; iPhone ต้องเพิ่มแอปไว้หน้าโฮมก่อน |
| แชตในกลุ่มทริป | ใช้ Firestore ที่มีอยู่ |

### มีก็ดี (ถ้ามีเวลา)

- ธีมปฏิทินโปสเตอร์ และธีมอื่นๆ
- แนะนำที่ใกล้ๆ จาก OpenStreetMap (Overpass), รายละเอียดและรูปสถานที่จาก Wikipedia
- "ว่างวันไหน": สมาชิกกลุ่มกดวันที่ว่าง เพื่อหาวันไปเที่ยวร่วมกัน
- สะสมจังหวัด

### ยังไม่ทำรอบนี้

- **รูปภาพ** (รูปในความทรงจำ, รูปปกทริป): ทำในเฟสหลัง พร้อมหาที่เก็บรูปแบบฟรี (ตัดสินใจแล้ว 23 ต.ค. 2569)

- งานอีเวนต์ไทยจาก TAT (รอ key)
- เวลาเดินทางระหว่างจุด (OpenRouteService)
- เช็คอินเบื้องหลังโดยไม่ต้องเปิดแอป (ต้องเป็นแอปมือถือจริง)
- หนังและรอบฉาย
- **LINE Official Account** แจ้งเตือนเรื่องสำคัญเข้า LINE (ไอเดียไว้ก่อน; แผนฟรีในไทยประมาณ 300 ข้อความ/เดือน นับต่อคนที่ได้รับ)

## 3. ขั้นตอน

| # | ขั้น | ถือว่าเสร็จเมื่อ |
|---|---|---|
| 1 | **วางขอบเขต** (ไฟล์นี้): ตกลง MVP, ตัดสินใจเรื่องแอปเดิม, เปิด backlog ใน GitHub | §2 ติ๊กครบและล็อก, คำถามใน §5 ตอบครบ |
| 2 | **ออกแบบข้อมูล**: คอลเลกชันใน Firestore สำหรับผู้ใช้ กลุ่ม แผน (จุดแวะอยู่ข้างใน) รายจ่าย สถานที่ งาน กระปุก + กฎความปลอดภัย (ใครอ่าน/เขียนอะไรได้) | เขียนไว้ในไฟล์นี้ และทดสอบกฎด้วย Firebase emulator |
| 3 | **ต่อข้อมูลจริงทีละส่วน**: ล็อกอิน → กลุ่ม + ลิงก์ชวน → แผน → เช็คอิน → รายจ่าย → สถานที่ เปลี่ยน store ของตัวทดลองเป็น Firestore โดยคงคำสั่งเดิมไว้ หน้าจอแทบไม่ต้องแก้ | มือถือ 2 เครื่องในกลุ่มเดียวกันเห็นการแก้ไขของกันและกัน, เทสต์การหารเงินและวันที่ผ่าน |
| 4 | **ความเร็วและมือถือ**: แยกโค้ดหนัก (three.js, Remotion) ให้หน้าแรกโหลดเร็ว, ทำ PWA | หน้าแรกโหลดไม่เกินราว 3 วินาที บนมือถือระดับกลางผ่าน 4G |
| 5 | **ขึ้นระบบ (ฟรี)**: Firebase Hosting หรือ Cloudflare Pages, โดเมนจริงไม่บังคับ | มีลิงก์ที่เพื่อนเปิดและติดตั้งได้ |
| 6 | **ให้เพื่อน 5 คนลองใช้** เก็บว่าอะไรพังและอะไรขาด | ความเห็นลง backlog และเลือกงานรอบถัดไปจากตรงนั้น |

ความปลอดภัยและการทดสอบทำในทุกขั้น ไม่ใช่ขั้นสุดท้าย

## 4. ปัญหาที่รู้แล้ว แก้ในขั้น 2

- **กฎ Firestore ของแอปเดิมเปิดกว้างเกินไป:**
  - ทุกทริปใครก็อ่านได้
  - ทริปที่บันทึกก่อนมี `ownerUid` ผู้ใช้คนไหนที่ล็อกอินก็แก้หรือลบได้
  - ผู้ใช้คนไหนที่ล็อกอินก็แก้รายชื่อสมาชิกของทริปได้
  - กฎใหม่: เฉพาะสมาชิกกลุ่มเท่านั้นที่อ่านและเขียนข้อมูลของกลุ่มได้
- **ไฟล์ดาวน์โหลดใหญ่:** ตอน build มีคำเตือนไฟล์ JS ก้อนใหญ่ (three.js, Remotion) แก้ในขั้น 4
- **ข้อมูลอยู่ในเบราว์เซอร์เดียว:** ข้อมูลตัวทดลองอยู่ใน localStorage ล้างเบราว์เซอร์แล้วหาย ใช้สาธิตได้ ขั้น 3 จะเปลี่ยนเป็นของจริง

## 5. ข้อตัดสินใจของขั้น 1 (ตอบครบแล้ว 23 ต.ค. 2569)

1. **แอปเดิม:** เลิกใช้ ตัวทดลองเป็นแอปหลัก ยกล็อกอิน Firebase และการเข้าร่วมด้วยลิงก์มาใช้
2. **ล็อกอิน:** Google + LINE (LINE ผ่าน Cloudflare Workers ฟรี)
3. **รูปภาพ:** ยังไม่มีในเวอร์ชันแรก ทำในเฟสหลังพร้อมหาที่เก็บรูปฟรี
4. **ใครแก้ทริปของกลุ่มได้:** ทุกคนในกลุ่ม; ลบกลุ่มได้เฉพาะคนสร้าง
5. **ที่ขึ้นระบบ:** Firebase Hosting แผนฟรี

**สถานะขั้น 1:** ✅ เสร็จ ขอบเขตใน §2 ล็อกแล้ว และเปิด backlog แล้ว 18 issue (ป้าย must / should / could / later)

**สถานะขั้น 2:** ✅ เสร็จ (รอคุณยืนยัน) โครงสร้างข้อมูลอยู่ที่ [DATA_MODEL.md](DATA_MODEL.md), กฎใหม่อยู่ที่ `firestore.rules`
ทดสอบบน emulator แล้ว 18 ข้อผ่านครบ (`npm run test:rules`) กฎยังไม่ได้นำขึ้นระบบจริง จะนำขึ้นในขั้น 3

**สถานะขั้น 3:** 🔄 กำลังทำ
