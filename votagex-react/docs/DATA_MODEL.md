# VOTAGEX โครงสร้างข้อมูล (ขั้น 2)

ข้อมูลของแอปบน Firebase Firestore (แผนฟรี Spark) แต่ละส่วนเก็บที่ไหน ใครอ่านหรือแก้ได้ และหน้าจอไหนดึงอะไร
กฎจริงอยู่ที่ [`firestore.rules`](../../firestore.rules) และชุดทดสอบอยู่ที่ [`tests/rules`](../tests/rules/firestore.rules.test.js)

อัปเดตล่าสุด: 23 ต.ค. 2569 (เพิ่มการโอนคืนและสลิป)

---

## หลักคิด

1. **ของกลุ่มอยู่ใต้กลุ่ม ของส่วนตัวอยู่ใต้ผู้ใช้** กฎจึงง่าย: เป็นสมาชิกกลุ่มก็เห็นทุกอย่างในกลุ่ม เป็นเจ้าของก็เห็นของตัวเอง
2. **ทริปที่ไปกับเพื่อนอยู่ในกลุ่มเสมอ** ถ้าสร้างทริปกับเพื่อนโดยไม่เลือกกลุ่ม แอปจะสร้างกลุ่มเล็กให้เองแบบซ่อน (`hidden: true`) ทริปคนเดียวอยู่ใต้ผู้ใช้
3. **จุดแวะ รายจ่าย ความทรงจำ แยกเป็นเอกสารย่อย** สองคนแก้พร้อมกันจะไม่ทับกัน เช่น เพื่อนเช็คอินพร้อมกันหลายคน
4. **ไม่ลบกลุ่มจริง** ใช้การเก็บกลุ่ม (`archived`) แทน ทริปยังอยู่และสมาชิกยังเปิดดูได้ ตรงกับที่ตกลงไว้ว่าลบกลุ่มแล้วทริปไม่หาย
5. **ตำแหน่ง GPS ไม่ขึ้นระบบ** เก็บแค่ผลเช็คอิน (เวลา, มาสายไหม, อัตโนมัติไหม)

## แผนผัง

```
users/{uid}                          โปรไฟล์: name, avatar
  private/settings                   ตั้งค่า: autoCheckIn, scope, calTheme, monthBudget, promptpay (สำเนาไป groups/*/members)
  places/{id}                        สถานที่ที่เซฟ
  events/{id}                        งานที่เก็บ (ยังไม่แชร์)
  plans/{pid}                        ทริปคนเดียว  ─┐ โครงเดียวกับทริปกลุ่ม
    stops/ expenses/ memories/                   ─┘
  jars/{jid}, jars/{jid}/log/{id}    กระปุกเก็บเงิน (ควรมี)

groups/{gid}                         name, icon, color, createdBy, memberIds[], archived, hidden?, joinCode?
  members/{uid}                      ข้อมูลของฉันในกลุ่ม: promptpay (ให้เพื่อนสแกนโอนคืน)
  events/{id}                        งานที่แชร์ให้กลุ่ม: …, sharedBy
  plans/{pid}                        name, kind, startDate, endDate, memberIds[] (คนที่ไป), currency, budget,
                                     destination, cover, checklist[], settled[], createdBy, groupId
    stops/{sid}                      date, time, name, area, lat, lng, cat, note, placeId?, eventId?,
                                     checkIns: { uid: { at, late, auto } }
    expenses/{eid}                   title, amount, currency, toTHB, cat, date, paidBy, splitIds[], createdBy
    payments/{xid}                   from, to, amount (บาท), status: sent | received, date, slip (มีสลิปไหม), by
    slips/{xid}                      from, to, image (JPEG ย่อขนาดแล้ว ≈ 50–150KB)   เห็นแค่ from กับ to
    memories/{mid}                   date, stopId?, text, mood, by   (รูปภาพ: เฟสหลัง)

invites/{code}                       groupId, createdBy, expiresAt (≤ 30 วัน)
```

ตัวทดลองเก็บข้อมูลเป็นก้อนเดียวใน `store.jsx` การย้ายจะคงชื่อคำสั่งเดิม (`addPlan`, `addStop`, `toggleCheckIn`,
`addExpense` …) แต่ข้างในเปลี่ยนเป็นเขียน Firestore หน้าจอแทบไม่ต้องแก้

## ใครทำอะไรได้

| ข้อมูล | อ่าน | สร้าง / แก้ | ลบ |
|---|---|---|---|
| โปรไฟล์ `users/{uid}` | ทุกคนที่ล็อกอิน | เจ้าของ | เจ้าของ |
| ของส่วนตัวใต้ `users/{uid}/…` | เจ้าของ | เจ้าของ | เจ้าของ |
| กลุ่ม | สมาชิก | สร้างได้โดยมีแค่ตัวเอง; สมาชิกแก้ชื่อ/ไอคอน/สี | ไม่ได้ (คนสร้างกดเก็บกลุ่มแทน) |
| เข้าร่วมกลุ่ม | — | ต้องมีลิงก์ชวนที่ยังไม่หมดอายุ และเพิ่มได้แค่ตัวเอง | ออกเองได้ (คนสร้างออกไม่ได้) |
| เอาคนออก / เก็บกลุ่ม | — | คนสร้างกลุ่มเท่านั้น | — |
| ลิงก์ชวน | คนที่รู้รหัส (ทีละอัน ห้ามไล่ดูทั้งหมด) | สมาชิกกลุ่ม | คนสร้างลิงก์ |
| ทริปของกลุ่ม | สมาชิก | สมาชิก; คนที่ไปต้องอยู่ในกลุ่ม | คนสร้างทริปหรือคนสร้างกลุ่ม |
| จุดแวะ | สมาชิก | สมาชิก; **เช็คอินได้เฉพาะของตัวเอง** | สมาชิก |
| รายจ่าย | สมาชิก | คนจ่ายและคนหารต้องเป็นคนที่ไปทริป; จำนวนต้องมากกว่า 0 | คนจดหรือคนจ่าย |
| การโอนคืน | สมาชิก | คนโอนบันทึก "โอนแล้ว" หรือคนรับบันทึก "ได้รับแล้ว" (เงินสด); **คนรับเท่านั้นที่ยืนยัน** | คนโอนหรือคนรับ |
| สลิป | **คนโอนกับคนรับเท่านั้น** | คนโอน | คนโอนหรือคนรับ |
| ความทรงจำ | สมาชิก | ของตัวเอง | ของตัวเอง |
| งานที่แชร์ | สมาชิก | คนแชร์ | คนแชร์ |
| พร้อมเพย์ `members/{uid}` | สมาชิกกลุ่มเดียวกัน | เจ้าของ | เจ้าของ |

คนที่ลบทริปได้ (คนสร้างทริปหรือคนสร้างกลุ่ม) ลบของข้างในได้ด้วย เพื่อให้ลบทริปทีเดียวหมด

ชุดทดสอบตรวจทุกข้อในตารางนี้ ทั้งกรณีที่ต้องผ่านและกรณีที่ต้องถูกปฏิเสธ (22 ข้อ ผ่านครบ)

**ทำไมสลิปอยู่ใน Firestore:** ที่เก็บไฟล์ของ Firebase (Storage) ต้องผูกบัตรตั้งแต่ 3 ก.พ. 2569 จึงย่อรูปสลิปแล้วเก็บเป็นเอกสาร
ใน Firestore แทน (เอกสารละไม่เกิน 1 MiB, โควตาฟรี 1 GiB เก็บได้ราวหมื่นใบ) และแยกเอกสารออกมาเพื่อให้กฎซ่อนจากคนอื่นในกลุ่มได้

## หน้าจอดึงอะไร

| หน้าจอ | ดึงอะไร |
|---|---|
| แถวกลุ่มบนหน้าแรก | `groups` ที่ `memberIds` มีฉัน |
| ปฏิทินของฉัน | ทริปทุกกลุ่มที่ฉันไป: collection group `plans` ที่ `memberIds` มีฉัน |
| ปฏิทินของกลุ่ม | `groups/{gid}/plans` |
| การ์ดของวัน | `…/plans/{pid}/stops` ของทริปวันนั้น |
| ใช้จ่ายรายเดือน (หน้าฉัน) | รายจ่ายของทุกทริปที่โหลดไว้แล้ว ไม่ต้องอ่านเพิ่ม |
| หน้าทริป แท็บเงิน | `…/plans/{pid}/expenses` และ `payments` (สลิปโหลดเมื่อกดดูเท่านั้น) |
| งบเที่ยวเดือนนี้ (หมู) | คำนวณในเครื่องจากรายจ่ายกับการโอนคืนของนัดในเดือนนั้น |
| เปิดลิงก์ชวน | `invites/{code}` แล้วเพิ่มตัวเองเข้า `groups/{gid}.memberIds` |

## โควตาฟรีพอไหม

Firestore แผนฟรี: อ่าน 50,000 / เขียน 20,000 / ลบ 20,000 ครั้งต่อวัน, เก็บได้ 1 GiB

ประมาณการช่วงให้เพื่อนลองใช้ (5 คน, เปิดแอปคนละ 20 ครั้งต่อวัน):
- เปิดหน้าแรก 1 ครั้งอ่านราว 50 เอกสาร (กลุ่ม ทริป จุดแวะ รายจ่ายของเดือน) และกฎความปลอดภัยที่ตรวจกลุ่มนับเป็นการอ่านด้วย
- 5 × 20 × 50 = **ราว 5,000 อ่านต่อวัน ใช้แค่ 10% ของโควตาฟรี**
- เขียน (เช็คอิน จดรายจ่าย แก้แผน) ไม่น่าเกินหลักร้อยต่อวัน

ถ้าเกินโควตา ระบบจะหยุดรับคำขอถึงเที่ยงคืนตามเวลาแปซิฟิก ไม่มีค่าใช้จ่ายเพราะไม่ได้ผูกบัตร

## กฎของแอปเดิม (`trips`)

ยังเก็บไว้จนกว่าจะเลิกใช้แอปเดิม แต่ปิดช่องโหว่แล้ว:
- **อ่าน:** ต้องล็อกอินก่อน
- **แก้หรือลบ:** ได้เฉพาะเจ้าของและสมาชิก
- **เข้าร่วม:** เพิ่มได้แค่ตัวเอง

**ผลข้างเคียง:** ทริปเก่าที่บันทึกก่อนมี `ownerUid` จะไม่มีใครแก้ได้ ถ้าต้องการเก็บไว้ ให้ย้ายข้อมูลตอนขั้น 3

## ทดสอบ

```
cd votagex-react
npm run test:rules
```

คำสั่งนี้เปิด Firestore emulator ในเครื่องด้วยโปรเจกต์ทดลอง `demo-votagex` รันชุดทดสอบ แล้วปิด emulator
ไม่แตะฐานข้อมูลจริง (ต้องมี Java และ Firebase CLI ซึ่งเครื่องนี้มีแล้ว)

**การนำกฎขึ้นระบบจริง** (`firebase deploy --only firestore:rules`) ยังไม่ได้ทำ จะทำในขั้น 3 พร้อมโค้ดที่ใช้โครงใหม่
เพราะกฎใหม่บังคับ "ต้องล็อกอินก่อนอ่านทริป" ถ้านำขึ้นตอนนี้ หน้าเข้าร่วมทริปของแอปเดิมที่เปิดก่อนล็อกอินอาจใช้ไม่ได้
